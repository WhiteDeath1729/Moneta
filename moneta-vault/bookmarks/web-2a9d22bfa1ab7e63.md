captured_text: "OPENMP C Examples of Parallel Programming with OpenMP OPENMP is a directory of C examples which\n      illustrate the use of the OpenMP application program interface\n      for carrying out parallel computations in a shared memory environment. The directives\n      allow the user to mark areas of the code, such as do , while or for loops, which are suitable for parallel\n      processing.  The directives appear as a special kind of \n      comment, so the program can be compiled and run in serial mode.  \n      However, the user can tell the compiler to \"notice\" the special\n      directives, in which case a version of the program will be created \n      that runs in parallel. Thus the same program can easily be run in serial or parallel mode \n      on a given computer, or run on a computer that does not have \n      OpenMP at all. OpenMP is suitable for a shared memory parallel system,\n      that is, a situation in which there is a single memory space, and\n      multiple processors.  If memory is shared, then typically the number\n      of processors will be small, and they will all be on the same\n      physical machine. By contrast, in a distributed memory system, items of data\n      are closely associated with a particular processor.  There may\n      be a very large number of processors, and they may be more loosely\n      coupled and even on different machines.  Such a system will need\n      to be handled with MPI or some\n      other message passing interface. OpenMP descended in part from the old Cray microtasking \n      directives, so if you've lived long enough to remember those, you \n      will recognize some features. C Issues OpenMP includes a number of functions whose type must be declared in\n      any program that uses them.  A user program calling OpenMP must have\n      the statement # include <omp.h> \"Pretend\" Parallelism OpenMP allows you to \"request\" any number of threads of execution.\n      This is a request, and it's not always a wise request.  If your system has\n      four processors available, and they're not busy doing other things, or serving\n      other users, maybe 4 threads is what you want.  But you can't guarantee\n      you'll get the undivided use of those processors.  Moreover, if you run the\n      same program using 1 thread and 4 threads, you may find that using 4 threads slows you down , either because you don't actually have 4 processors,\n      (so the system has the overhead of pretending to run in parallel), or because\n      the processors you have are also busy doing other things. For this reason, it's wise to run the program at least once in single thread mode,\n      so you have a benchmark against which to measure the speedup you got (or didn't\n      get!) versus the speedup you hoped for. Compiler Support The compiler you use must recognize the OpenMP directives in order to produce\n      code that will run in parallel.  Here are some of the compilers available that\n      support OpenMP: The GNU compilers gcc/g++ (version 4.2 or later) \n          and gfortran (version 2.0 or later). The IBM compilers xlc and xlf . The Intel compilers icc , icpc and ifort . The Microsoft Visual C++ compiler. The Portland Group C/C++ and Fortran compilers. Sun Studio C/C++ and Fortran95 compilers. Licensing: The computer code and data files described and made available on this web page \n      are distributed under the GNU LGPL license. Languages: OPENMP examples are available in a C version and a C++ version and a FORTRAN90 version .
